## CORE PHILOSOPHY

Zayne UI is not a utility framework. It is a **CSS token-driven component engine** built on:

- Pure HTML / CSS / JS
- PHP constructs default styles
- Blade renders structure only
- CSS variables drive all theming
- Alpine.js strictly for overlay DOM state
- Zero Tailwind dependency

## ARCHITECTURE LAYERS

```
┌─────────────────────────────────────────────────────────┐
│  DEV USAGE (Blade template)                             │
│  <x-zayne.action.button variant="solid"                 │
│      color="primary" padding="12px 24px" />             │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  COMPONENT PHP CLASS                                    │
│  - defines props + CSS defaults in __construct          │

│  - mount() only if component has variants               │
│  - resolves variant styles via HasColorVariants trait   │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  STYLE ENGINE  (ZayneComponent base class)              │
│  - mergeStyles()     merges base + variant arrays       │
│  - toStyleString()   converts array → CSS string        │
│  - only used by components that have variants           │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  BLADE TEMPLATE                                         │
│  - pure HTML structure only                             │
│  - Layout/Data: props output directly in style=""       │

┌──────────────────────────▼──────────────────────────────┐
│  CSS FILES                                              │
│  zayne-theme.css       tokens, colors, shadows          │

└─────────────────────────────────────────────────────────┘
```

## BASE COMPONENT CLASS

```php
<?php

namespace App\View\Components\Zayne;

use Illuminate\View\Component;

abstract class ZayneComponent extends Component
{
    protected string $style = '';

    /**
     * Merge multiple style arrays into one.
     * Used only by components that have variants.
     */
    protected function mergeStyles(array ...$styles): array
    {
        return array_merge(...array_filter($styles));
    }

    /**
     * Convert style array → inline CSS string.
     * Used only by components that have variants.
     */
    protected function toStyleString(array $styles): string
    {
        return collect($styles)
            ->filter()
            ->map(fn($value, $key) => "{$key}: {$value}")
            ->implode('; ');
    }
}
```

## CSS FILE RESPONSIBILITIES

### zayne-theme.css ✅ editable

The only file developers are allowed to edit.

- All color tokens
- Shadow tokens
- Radius tokens
- Size tokens
- Per-theme overrides (`light`, `dark`, `abyss`)

```css
.light {
    --zayne-color-primary:         oklch(28% 0.01 271);
    --zayne-color-primary-content: oklch(98% 0.002 271);
    --zayne-custom-sidebar:        #ffffff;
    --zayne-custom-layout-shadow:  0 8px 10px rgba(0,0,0,0.08);
}
```

### zayne-layout.css ❌ locked

Structure only. Zero color. Zero font.

- CSS grid root (`.zaynemainlayout`)
- Sidebar width transitions
- Structural class hooks (`.zayne-header-left`, `.zayne-sidebar-body`, etc.)
- Component structural hooks (`.zayne-button`, `.zayne-button--sm`, etc.)
- Sidebar collapse behavior
- `sidebar-label` hide/show logic
- Pseudo-class behavior (`:focus-visible`, `:active`, `:hover`)
- Mobile layout behavior — hardcoded `768px` breakpoint
- Mobile floating toggle button position and structure
- Mobile drawer positioning and backdrop
- Scrollbar utilities

### zayne-animations.css ❌ locked

Motion only. Used exclusively by Overlay components and mobile drawer.

- Keyframe definitions
- Enter/leave animation classes
- Mobile drawer slide-in/out animations
- Custom easing vars (`ease-out-smooth`, `ease-spring`)

```css
.zayne-modal-enter    { animation: zayne-modal-in   260ms var(--ease-out-smooth) forwards; }
.zayne-modal-leave    { animation: zayne-modal-out  140ms var(--ease-in-smooth)  backwards; }
.zayne-backdrop-enter { animation: zayne-fade-in    180ms var(--ease-out-smooth) forwards; }
.zayne-backdrop-leave { animation: zayne-fade-out   120ms var(--ease-in-smooth)  backwards; }
.zayne-drawer-enter   { animation: zayne-drawer-in  260ms var(--ease-out-smooth) forwards; }
.zayne-drawer-leave   { animation: zayne-drawer-out 200ms var(--ease-in-smooth)  backwards; }
```

## MOBILE LAYOUT

### Behavior

The layout has two modes separated by a hardcoded `768px` breakpoint.

|  | Desktop (≥768px) | Mobile (<768px) |
| --- | --- | --- |
| Sidebar | Visible, fixed position | Hidden |
| Navigation | Sidebar | Drawer sliding from left |
| Toggle | None | Floating button, bottom left |
| Backdrop | None | Dark overlay with blur |

### Breakpoint

Hardcoded in `zayne-layout.css`. Never a CSS variable. Never a PHP prop.
Keeping it hardcoded makes the layout stable and eliminates a class of
layout-breaking bugs that come from configurable breakpoints.

```css
@media (max-width: 768px) { ... }
```

### Floating Toggle Button

A raw HTML element in the layout Blade template. Not a Zayne component.
No PHP class. No props. Styled entirely via `zayne-layout.css` and
`zayne-theme.css` tokens.

- Fixed position, bottom left corner
- Always on top (`z-index` in `zayne-layout.css`)
- Hidden on desktop, visible on mobile only
- Renders a hamburger/close icon depending on drawer state
- Controlled by Alpine on the root layout wrapper

```
{{-- Raw element — not a component --}}
<button
    class="zayne-mobile-toggle"
    x-on:click="mobileOpen = !mobileOpen"
    x-show="!mobileOpen"
>
    <svg .../>
</button>
```

### Drawer

On mobile the sidebar becomes a drawer. It is the same sidebar element —
`zayne-layout.css` repositions it at the `768px` breakpoint. No second
sidebar component. No duplication.

- Slides in from the left
- Sits above all content
- Closes when backdrop is tapped

### Backdrop

Dark overlay with blur. Raw element in the layout Blade template.
Not a component. Tapping it sets `mobileOpen = false`.

```
<div
    class="zayne-mobile-backdrop"
    x-show="mobileOpen"
    x-cloak
    x-on:click="mobileOpen = false"
    x-bind:class="mobileOpen ? 'zayne-backdrop-enter' : 'zayne-backdrop-leave'"
></div>
```

```css
/* zayne-layout.css */
.zayne-mobile-backdrop {
    position: fixed;
    inset: 0;
    z-index: 40;
    backdrop-filter: blur(4px);
    -webkit-backdrop-filter: blur(4px);
    background: rgba(0, 0, 0, 0.5);
}
```

### Alpine State

The mobile drawer is the one case where Alpine lives on a Layout component.
This is the explicit exception — the root layout wrapper carries `x-data`
because the drawer is overlay behavior attached to a layout shell.

```
<div
    class="zaynemainlayout"
    x-data="{ sidebarCollapsed: false, mobileOpen: false }"
>
```

Two state values:

- `sidebarCollapsed` — desktop sidebar collapsed/expanded (existing)
- `mobileOpen` — mobile drawer open/closed (new)

## STANDARD OPERATING PROCEDURE

---

### STEP 1 — DEFINE COMPONENT ROLE

Before writing a single line of code, answer these four questions:

```
1. What type is it?         Layout / Visual / Action / Overlay / Data / Feed / Form
2. What does it do?         Structure / Appearance / Behavior / All three?
3. Does it need variants?   Yes (Visual, Action, Overlay, Feed, Form) / No (Layout, Data)
4. Does it need Alpine?     Yes (Overlay only, or root layout for mobile) / No (everything else)
```

If you cannot answer all four — stop. You are not ready to build it.

---

### STEP 2 — DEFINE STYLE API

Decide which props the developer is allowed to override.

```
ALWAYS expose:       padding, margin, radius, shadow, gap
EXPOSE if needed:    border, background, color
NEVER expose:        font-size, line-height, icon-size, z-index, width, height
```

Directional props (`margintop`, `borderleft`) are only added when shorthand is not enough.

### The two prop patterns

**Props with a Zayne default** — always carry a token value. Never `unset`.

These are properties Zayne has an opinion on. The token provides the default;
the dev overrides it when they want something different.

```php
public string $padding    = '0px 1rem',
public string $background = 'var(--zayne-custom-header)',
public string $shadow     = 'var(--zayne-custom-layout-shadow)',
public string $radius     = 'var(--zayne-radius-field)',
```

Dev override:

```
<x-zayne.layout.header background="#290323" shadow="none" />
```

**Props that are off by default** — default to `'unset'`.

These are properties Zayne has no opinion on. They pass through to the browser
as `unset`, which the browser treats as "do nothing". The dev turns them on when needed.

```php
public string $border       = 'unset',
public string $bordertop    = 'unset',
public string $borderbottom = 'unset',
public string $borderleft   = 'unset',
public string $borderright  = 'unset',
public string $bordercolor  = 'unset',
public string $margin       = 'unset',
public string $margintop    = 'unset',
public string $marginbottom = 'unset',
public string $marginleft   = 'unset',
public string $marginright  = 'unset',
```

Dev override:

```
{{-- Full border --}}
<x-zayne.layout.header border="1px" bordercolor="var(--zayne-color-base-border)" />

{{-- Top border only --}}
<x-zayne.layout.header bordertop="1px" bordercolor="var(--zayne-color-base-border)" />
```

> **Why `'unset'` and not `'null'`**
> 
> 
> `'null'` is not valid CSS — the browser ignores it but still outputs
> `border-width: null;` in every rendered element, polluting the DOM.
> `unset` is a real CSS keyword meaning "revert to initial value", which for
> non-inherited properties like border and margin is effectively "off".
> 

---

### STEP 3 — CONNECT TO THEME TOKENS

Every default must reference `zayne-theme.css`. Never hardcode values.

```php
// ✅ Correct
public string $background = 'var(--zayne-custom-sidebar)';
public string $color      = 'var(--zayne-color-base-content)';
public string $shadow     = 'var(--zayne-custom-layout-shadow)';
public string $radius     = 'var(--zayne-radius-field)';

// ❌ Wrong
public string $background = '#ffffff';
public string $color      = '#222222';
public string $shadow     = '0 4px 6px rgba(0,0,0,0.1)';
public string $radius     = '8px';
```

---

### STEP 4 — DOES THIS COMPONENT NEED mount()?

This is the key decision before writing any style logic.

```
Does this component have variants?
  No  →  props output directly in Blade style=""    (Layout, Data)
  Yes →  mount() resolves variant, builds $style    (Action, Visual, Feed, Form, Overlay)
```

`mount()` exists for one reason only: **variant resolution**. If a component has
no variants, it has no `mount()`, no `$style`, and does not use the style engine.

---

### STEP 5 — LAYOUT / DATA: DIRECT BLADE OUTPUT

No `mount()`. No `$style`. Props output directly in the Blade `style=""` attribute.
This works cleanly because every prop is already valid CSS — either a token,
a real value, or `unset`.

```
<header
    class="zayne-header"
    style="
        padding:             {{ $padding }};
        background:          {{ $background }};
        border-radius:       {{ $radius }};
        gap:                 {{ $gap }};
        box-shadow:          {{ $shadow }};
        margin:              {{ $margin }};
        margin-top:          {{ $margintop }};
        margin-bottom:       {{ $marginbottom }};
        margin-left:         {{ $marginleft }};
        margin-right:        {{ $marginright }};
        border-width:        {{ $border }};
        border-top-width:    {{ $bordertop }};
        border-bottom-width: {{ $borderbottom }};
        border-left-width:   {{ $borderleft }};
        border-right-width:  {{ $borderright }};
        border-color:        {{ $bordercolor }};
    "
    {{ $attributes }}
>
    @isset($left)
        <div class="zayne-header-left">{{ $left }}</div>
    @endisset

    <div class="zayne-header-center">{{ $slot }}</div>

    @isset($right)
        <div class="zayne-header-right">{{ $right }}</div>
    @endisset
</header>
```

### STEP 6 — ACTION / VISUAL / FEED / FORM / OVERLAY: mount() + $style

`mount()` resolves the variant and merges it with the base style array.
Blade receives a single compiled `$style` string.

```php
public function mount(): void
{
    $base = [
        'padding'       => $this->padding,
        'gap'           => $this->gap,
        'border-radius' => $this->radius,
        'box-shadow'    => $this->shadow,
        'margin'        => $this->margin,
        'border-width'  => $this->border,
        'border-color'  => $this->bordercolor,
    ];

    $variant = $this->resolveVariantStyles();

    $this->style = $this->toStyleString(
        $this->mergeStyles($base, $variant)
    );
}
```

Blade receives `$style` as a compiled string:

```
<element
    class="zayne-{component}"
    style="{{ $style }}"
    {{ $attributes }}
>
```

### STEP 7 — VARIANT SYSTEM

Used only by Visual, Action, Overlay, Feed, and Form components. Never by Layout or Data.

```php
<?php

namespace App\View\Components\Zayne\Traits;

trait HasColorVariants
{
    protected function resolveVariantStyles(): array
    {
        $variant = $this->variant ?? 'solid';
        $color   = $this->color   ?? 'primary';

        return $this->variantMap()[$variant][$color]
            ?? $this->variantMap()[$variant]['base']
            ?? $this->variantMap()['solid']['primary'];
    }

    protected function variantMap(): array
    {
        return [

            // Full background
            'solid' => [
                'primary'   => ['background' => 'var(--zayne-color-primary)',   'color' => 'var(--zayne-color-primary-content)'],
                'secondary' => ['background' => 'var(--zayne-color-secondary)', 'color' => 'var(--zayne-color-secondary-content)'],
                'danger'    => ['background' => 'var(--zayne-color-danger)',     'color' => 'var(--zayne-color-danger-content)'],
                'success'   => ['background' => 'var(--zayne-color-success)',    'color' => 'var(--zayne-color-success-content)'],
                'warning'   => ['background' => 'var(--zayne-color-warning)',    'color' => 'var(--zayne-color-warning-content)'],
                'info'      => ['background' => 'var(--zayne-color-info)',       'color' => 'var(--zayne-color-info-content)'],
                'base'      => ['background' => 'var(--zayne-color-base-200)',   'color' => 'var(--zayne-color-base-content)'],
            ],

            // Tinted background, colored text
            'soft' => [
                'primary'   => ['background' => 'color-mix(in oklch, var(--zayne-color-primary)   15%, transparent)', 'color' => 'var(--zayne-color-primary)'],
                'secondary' => ['background' => 'color-mix(in oklch, var(--zayne-color-secondary) 15%, transparent)', 'color' => 'var(--zayne-color-secondary)'],
                'danger'    => ['background' => 'color-mix(in oklch, var(--zayne-color-danger)     15%, transparent)', 'color' => 'var(--zayne-color-danger)'],
                'success'   => ['background' => 'color-mix(in oklch, var(--zayne-color-success)    15%, transparent)', 'color' => 'var(--zayne-color-success)'],
                'warning'   => ['background' => 'color-mix(in oklch, var(--zayne-color-warning)    15%, transparent)', 'color' => 'var(--zayne-color-warning)'],
                'info'      => ['background' => 'color-mix(in oklch, var(--zayne-color-info)       15%, transparent)', 'color' => 'var(--zayne-color-info)'],
                'base'      => ['background' => 'var(--zayne-color-base-200)',                                         'color' => 'var(--zayne-color-base-content)'],
            ],

            // Transparent + colored border + colored text
            'outline' => [
                'primary'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-primary)',      'border' => '1px solid var(--zayne-color-primary)'],
                'secondary' => ['background' => 'transparent', 'color' => 'var(--zayne-color-secondary)',    'border' => '1px solid var(--zayne-color-secondary)'],
                'danger'    => ['background' => 'transparent', 'color' => 'var(--zayne-color-danger)',        'border' => '1px solid var(--zayne-color-danger)'],
                'success'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-success)',       'border' => '1px solid var(--zayne-color-success)'],
                'warning'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-warning)',       'border' => '1px solid var(--zayne-color-warning)'],
                'info'      => ['background' => 'transparent', 'color' => 'var(--zayne-color-info)',          'border' => '1px solid var(--zayne-color-info)'],
                'base'      => ['background' => 'transparent', 'color' => 'var(--zayne-color-base-content)', 'border' => '1px solid var(--zayne-color-base-border)'],
            ],

            // Transparent + dashed border
            'dashed' => [
                'primary'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-primary)',      'border' => '1px dashed var(--zayne-color-primary)'],
                'danger'    => ['background' => 'transparent', 'color' => 'var(--zayne-color-danger)',        'border' => '1px dashed var(--zayne-color-danger)'],
                'base'      => ['background' => 'transparent', 'color' => 'var(--zayne-color-base-content)', 'border' => '1px dashed var(--zayne-color-base-border)'],
            ],

            // Transparent, subtle hover
            'ghost' => [
                'primary'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-primary)'],
                'danger'    => ['background' => 'transparent', 'color' => 'var(--zayne-color-danger)'],
                'base'      => ['background' => 'transparent', 'color' => 'var(--zayne-color-base-content)'],
            ],

            // Text only, underline
            'link' => [
                'primary'   => ['background' => 'transparent', 'color' => 'var(--zayne-color-primary)',      'text-decoration' => 'underline'],
                'danger'    => ['background' => 'transparent', 'color' => 'var(--zayne-color-danger)',        'text-decoration' => 'underline'],
                'base'      => ['background' => 'transparent', 'color' => 'var(--zayne-color-base-content)', 'text-decoration' => 'underline'],
            ],

        ];
    }
}
```

### STEP 10 — STRUCTURAL CSS

Structural hooks go in `zayne-layout.css`. Written once, never touched again.

### Why structural CSS cannot be replaced by inline styles or PHP

Three things inline styles fundamentally cannot do:

**1. Pseudo-classes** — `:hover`, `:focus-visible`, `:active` have no selector
scope in inline styles. They must live in a CSS class.

**2. Transitions** — `transition: all 200ms` needs a persistent class that
survives state changes. Inline transitions are static; they cannot interpolate
between states.

**3. Compound selectors** — `.zayne-button--md.zayne-button--square` combines
two classes into one rule. PHP can write `width: 2.5rem` inline, but a CSS class
can be overridden by specificity. An inline style requires `!important` to override.

**Rule of thumb:** If it involves a selector → CSS. If it involves a value → PHP / Blade.

## HARD RULES

```
❌  No Tailwind classes anywhere in any component
❌  No TailwindMerge
❌  No hardcoded hex, rgb, or hsl color values
❌  No logic or calculations in Blade
❌  No raw prop values in style= on variant components (always goes through $style)
❌  No variants on Layout or Data components
❌  No $tag prop  (href present = <a>,  no href = <button>)
❌  No @if for slot checks  (always use @isset)
❌  No Alpine outside of Overlay components or the root layout wrapper
❌  No x-data anywhere except Overlay root elements and the root layout wrapper
❌  No 'null' string as a prop default  (use 'unset' for off-by-default props)
❌  No PHP null as a prop default
❌  No mount() on Layout or Data components
❌  No configurable mobile breakpoint  (hardcoded 768px in zayne-layout.css only)
❌  No mobile toggle as a Zayne component  (raw HTML element in layout Blade only)

✅  Every default prop references zayne-theme.css tokens
✅  Off-by-default props use CSS 'unset' as their default value
✅  Layout / Data props output directly in Blade style=""
✅  Action / Visual / Feed / Form / Overlay use mount() + $style
✅  mount() exists only for variant resolution — nothing else
✅  Every component passes $attributes through untouched
✅  Slot names are always consistent across all components
✅  Pseudo-classes, transitions, and compound selectors live in zayne-layout.css
✅  Mobile breakpoint is hardcoded at 768px in zayne-layout.css
✅  Mobile sidebar reuses the same element as desktop — CSS repositions it
✅  Mobile state (mobileOpen) lives on the root layout wrapper x-data only
✅  x-data lives on root wrapper only (Overlay) or root layout wrapper (mobile)
✅  x-cloak on every Alpine-controlled element
✅  x-trap on Modal and Drawer panels
✅  Animation classes come from zayne-animations.css only
✅  Structural CSS hooks go in zayne-layout.css only
✅  One PHP class file + one Blade file per component, always
```
